# CR07 · Build a relationship diagram, then return to conviction

Version `2026-09-10.3` · [Original reel](https://www.instagram.com/reel/DdB2yRaDz0M/) · 39.509s

**Message:** A customer's problem plus your distinct solution generates an idea; different angles turn it into content.

**Story:** Problem node → add solution → create idea → branch into angles → relabel as content → return to the person for qualification and application.

**Format foundation:** The upper pane externalizes a relationship the viewer would otherwise have to hold in memory. The lower pane preserves the speaker's gestures as he assembles it. The split ends when the task changes from understanding the mechanism to hearing a qualification.

**Good adaptation:** Build only the relationship currently named. Keep the original idea visible as branches arrive. Fit the speaker deliberately so gestures remain legible; do not contain an entire landscape frame at tiny scale. Keep captions separate from node labels. Hold the finished relationship before returning to a full presenter view.

**Limits and counterexample:** Do not select this format for a personal judgment with no relationship to diagram. Do not copy six branches unless the new explanation supports six. The final claimed 25 ideas is not a demonstrated multiplication in the graphic. This is a collaborative podcast post, not evidence of a universal Caleb editing preset.

**Text roles:** Black node labels on yellow circles, white speech captions above a thin yellow separator, black textured diagram background. Transfer the label/caption distinction and visual hierarchy, not the palette or exact font.

**Compare:** CR04, N07-B22, N03-B06. See [Format foundations](../../FORMAT_FOUNDATIONS.md).

**Possible mechanisms:** `constellation-hub`, `flowchart-vertical`, `native-stacked-media`. These require configuration/composition and review; they are not rendered matches.
