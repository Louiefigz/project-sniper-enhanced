## Reuse rather than a parallel system

The [shared optimization map](SHORTS_SHARED_OPTIMIZATION_MAP_2026-09-10.md)
records the intended reuse. Code inspection confirms that V9 uses existing
proposal preparation, retained speech timing, clause/frame validation,
immutable storage, input verification, leases, clocks and timing journals.
Native caption grouping calls the existing Python grouping policy.

Keep the existing native preflight, managed preview, dependency closure,
resource supervision and render infrastructure. Connect Shorts through narrow
adapters for portrait direction, catalog/asset binding and native project
review. Do not regenerate an authored native project through
`studio_review.py`'s flattened-base graphics projection.

The intended primary route is: story requirement → HyperFrames catalog search
→ inspected item source and inputs → configuration/composition with real assets
→ editable native Studio project → audiovisual qualification. Reuse the
long-form native catalog workflow, not the old local-list restriction.
The producer-study instructions already explicitly prohibit limiting native
projects to the legacy local template list. Current V9's two fixed mechanisms
are only a development fixture; they do not implement that primary route.

The long-form audit does not establish a quality-approved two-hour workflow.
Its recorded complete revision took 3h08m19.598s and retained explicit quality
limits. Shorts speed needs its own measured end-to-end proof; shared helpers
alone do not establish a runtime improvement.

## Remaining implementation and acceptance

1. **Native API/UI route:** expose explicit V9 selection, project publication
   and managed preview opening through the existing application. The current
   default remains V5; inspected writer callers are test/development callers.
2. **Story and hook selection:** connect the existing YouTube formula selection
   to actual recorded speech, first visual, supported promise and payoff.
   The current RAG hook adapter is not a Sniper integration.
3. **Primary HyperFrames catalog and assets:** carry selected item, source/version/hash, supported
   inputs, adaptation and admitted asset dependencies into executable scenes.
   Current V9 blocks required outside assets and has no generic catalog binding.
   The existing discovery tool already finds `message-thread-reveal`,
   `thread-message-stack`, `chat-message` and `chat-thread`; their execution
   qualification must be explicit. Catalog-driven composition is a required
   central connection, not optional expansion of a local Sniper catalog.
4. **Portrait views and authentic evidence:** the current presenter uses a
   contained 1080 × 660 region. This is not the requested full-frame portrait
   opening or continuous face tracking. Reference staging then accepted only
   sequence-case IDs, so single entries were not selectable through that
   interface (the third-party study cases were withdrawn from the product on 2026-09-18).
5. **Native review and edits:** establish native audiovisual review, edit
   persistence/reload and completion ownership. Legacy readiness/opening/body
   paths correctly reject V9 instead of granting inappropriate approval.
6. **Incremental work and export:** connect scene/source dependencies to the
   existing render graph and prove a scoped revision preserves unaffected
   scenes, caption timing and audio. A pure file-comparison test is useful but
   does not establish incremental media export or Studio edit synchronization.
7. **One complete Short:** verify supported hook, source truth, acquired assets,
   readable changes/holds, face and hand clearance, audio, forward/reverse seek,
   restart, reload and requested encoded output before generalizing to all three.
