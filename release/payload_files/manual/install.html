Install and first use

You use Sniper from your own Codex or Claude Code: open the Sniper folder there and ask. Setup is mostly downloads, and it is safe to run again: it redoes only what did not finish.

Step 0 — check the download is the file it should be

Beside the download there is a checksum file. Compare it with the archive you received:

shasum -a 256 project-sniper-<version>-mac.zip

The value must match the one in SHA256SUMS. If it does not, the file is incomplete or altered — download it again and do not install it. The real checksum is only ever published outside the archive; a hash inside a file cannot verify that file.

Step 1 — unzip somewhere sensible

Your home folder or ~/Applications is fine. Two constraints:

  • No comma, apostrophe, colon or backslash in the folder path. The audio-cleanup filter embeds this folder's path and cannot handle those characters. Any other character — spaces, accents, $, quotes — is fine: Sniper stores its settings literally. The installer checks and tells you if the path is unusable; this is a known limit, not something the installer fixes.
  • Not on a drive you unplug, and not in a folder that syncs to cloud storage — render caches are large and will fight the sync.

This folder is the one you open in Codex or Claude Code. Your video projects go in its projects folder unless you choose another (see Step 3).

Step 2 — nothing to install first

Sniper brings its own tools. The first setup downloads them from conda-forge (the open-source package collection), checks every file against the SHA-256 recorded for this release before using it, and installs them into ~/.project-sniper. You do not need Homebrew, Xcode, Python, Node or any of these:

About 300 MB is downloaded once; the tools take about 1.2 GB on disk. Your own Homebrew, Python, Node or conda are not used or changed, even when they come first on your PATH. Sniper folders of the same release share one copy of the tools; uninstalling the last of them removes it. If the download stops, run setup again: it resumes and checks what arrived.

Which Macs. Any Apple silicon Mac (M1 or later) with its free macOS updates: macOS 13.5 or newer, which every Apple silicon Mac can install and the oldest these tools run on. So far only macOS 26 has actually been tested. On an Intel Mac or an older macOS, setup stops before downloading anything and says why.

Your home folder path must not contain a space (macOS account names never do): the tools live there because Studio needs a Node path without spaces, and this folder may have them.

Sniper's ffmpeg. The renderer needs two ffmpeg filters (zscale and rubberband) that no ready-made Mac build carries, so Sniper builds ffmpeg itself from the unmodified FFmpeg 8.0.3 and Rubber Band 4.0.0 sources. It ships in this download (install/deps/), with those sources in third-party/sources/ (GPL) and the build recipe inside the ffmpeg archive (share/sniper-ffmpeg/). Setup checks its SHA-256 and installs it the same way as the downloaded tools. It is not yet signed with an Apple Developer ID.

Step 3 — open the folder in Codex or Claude Code and say “Set up Sniper”

You need your own Codex (a ChatGPT plan) or Claude Code (a Claude plan), desktop app or command line, signed in as usual. Sniper installs no copy of either and never asks you to sign in to anything: it runs on the subscription you already use. Open this folder there and ask:

Set up Sniper.

Your agent runs ./sniper setup (the same as install/install.command), which takes several minutes, mostly downloads. It asks your permission before running commands, as it always does. With Codex, it may also ask to run a step outside its own sandbox: setup downloads into ~/.project-sniper, and Sniper's video check starts its own macOS sandbox, which cannot start inside Codex's. Approve those; Sniper's check still runs in its own sandbox.

If you prefer not to let your agent install, double-click install/setup.command in Finder instead: it does the same in a Terminal window. It is not yet signed, so the first time macOS stops it. On macOS 13.5–14, right-click it and choose Open. On macOS 15 or later that no longer works: after the warning, open System Settings › Privacy & Security and click Open Anyway next to the message about the script. Neither route has yet been seen on a clean Mac.

Your projects go in this folder's projects folder, where Codex can work without extra approvals. To keep them somewhere else, run setup once with install/install.command --workspace /path/to/folder (Codex will then ask before it writes there).

What setup does, in order:

  1. Installs Sniper's own tools (above) — or, when they are already there, checks every one of their files against what was installed and that each tool runs, including every ffmpeg feature the renderer uses.
  2. Installs the JavaScript dependencies Sniper's scripts use into node_modules (npm checks every package against the integrity hash in the lockfile).
  3. Installs the rendering project's dependencies into templates/motion/node_modules, the same way.
  4. Creates .venv from a pinned list, so you get exactly the Python package versions this release was tested with; every download must match its recorded SHA-256.
  5. Downloads the exact rendering browser into runtime/browser and checks its SHA-256 against the one recorded for this release.
  6. Puts the speech model in runtime/whisper. If an identical copy is already on your Mac it reuses it; otherwise it downloads about 465 MB. The file must match its recorded checksum.
  7. Writes this install's settings to runtime/sniper.env.
  8. Builds the rendering runtime.

Then it runs the checker (./sniper doctor). In a Terminal window it first offers the optional Deepgram connection (Step 4).

If it stops, run it again. Each step records what it finished with and the checksum of every file it produced. A step that did not finish, whose inputs changed, or whose files no longer match is removed and redone; a finished, intact one is skipped. You never have to delete anything by hand. An interrupted download resumes from where it stopped; a partial download that turns out wrong is fetched again from the start. Your own settings in runtime/sniper.local.env are never overwritten.

Setup runs only while no Sniper command is running: let running edits and renders finish first. If something is still using this folder, setup says what and changes nothing.

Step 4 — connect Deepgram (optional)

Local transcription is included and needs no key. If you also want Deepgram, double-click install/setup.command in Finder (or run it in Terminal) and choose Connect/replace key. Create a key at Deepgram Console and paste it at the hidden prompt — in that Terminal window, never into a conversation with your agent. Setup checks the key with Deepgram before saving it. A failed check keeps any previous key. You can retry or skip.

Deepgram is billed separately by Deepgram. Using it sends audio to Deepgram. The connection check sends no audio and does not prove your balance or every model permission. Connecting does not authorize paid transcription: approve it for the specific edit when you ask your agent to use Deepgram.

The key is saved in runtime/deepgram.env, readable only by your Mac account, and loaded by Sniper's commands. It is not part of the diagnostic bundle. Reopen install/setup.command to replace or remove it without editing files. Removal disconnects this install; revoke the key in Deepgram Console to invalidate it.

Which model

Whatever you use in your Codex or Claude Code. Sniper does not choose or send a model; its instructions and skills work with either app. Your own settings for Sniper's commands (for example a different video folder, SNIPER_WORKSPACE_ROOT='/Volumes/Work/Client $97') go in runtime/sniper.local.env, which is read as shell: put a value that contains $, a backtick, a backslash, quotes or spaces in single quotes.

Step 5 — make your first edit

With the Sniper folder open in Codex or Claude Code, say “Help me make my first edit from my own video.” Your agent reads Sniper's instructions and skills from this folder and runs Sniper's commands through ./sniper, which uses Sniper's own tools whatever else is on your Mac.

To check the install at any time, ask your agent to run ./sniper doctor (or double-click install/doctor.command). The checker asks the product's own code what it would use, admits a generated video sample through Sniper's own sandbox and runs a short real transcription of speech it generates on your Mac, without running an edit.
