Asking for a change, and not losing work

How to get one thing fixed without the rest of the edit being rebuilt around you.

Ask for the smallest true thing

Revisions work best when they name the defect, not the desired redesign. Compare:

WorksWorks badly
"The caption at 0:14 is covering my face — move it up." "Make the captions better."
"Cut the false start at the very beginning, before 'so basically'." "Tighten the intro."
"The card at 1:02 says 40% but I said 'about a third'. Fix the number." "Check the graphics."
"Too much zooming in the second half — halve it." "Less motion."

A named defect gets a minimal change. A vague one gets a broader rebuild, because it cannot tell which part you meant.

What is protected when you ask for a change

  • Work you approved is not silently redone. Sniper reuses the parts of the edit your change does not touch — but only while the plan, the source and the tools still hash the same. If anything upstream changed, it rebuilds rather than reusing something stale.
  • An approval is bound to exact bytes. A finished video counts as approved only while its plan, its asset list, its own bytes and the completed job all still match. Changing the plan invalidates the approval rather than leaving it attached to a different video.
  • You are told which happened. The receipt says whether the change was a bounded reuse or a larger rebuild. If a change is too broad or unsupported it stops for your decision instead of guessing.

Interrupting, resuming and reopening

  • Keep the conversation open while a render runs. Your agent runs each step as a command; closing its window or the Mac sleeping can stop a step part-way.
  • If a step stops, ask your agent to run it again. Finished stages are reused when their inputs have not changed, and a long export picks up a compatible earlier attempt, so it does not start from the beginning.
  • Reopening a project later — open the Sniper folder in your agent and name the project in projects/<project>/. Its state is read from what is actually on disk, not from a log, so a project you left months ago still reports accurately.
  • One edit at a time per project. Keep as many projects as you like.

Confirming the change is really in the video

A revision is not done because the tool said "done". Confirm it in the encoded output: play the new export and look at the moment you asked about. If you also adjusted graphics in the editable project, both views have to show the same thing — see Reviewing the video and opening the editable project.
