# A review note is not a prebuild boundary

Aaron rated the first IMG_7446 long-form edit 7/10 after it passed technical
checks. He reported abrupt presenter moves, repeated grooming footage,
context-free food pictures, missing Facebook-payment support and an unreadable
supplier view. The 145.93-second file decoded correctly. That did not establish
that its visual explanation worked.

The correction applies to future Shorts and long-form work within the requested
treatment. A simple edit still may need no supporting graphics. The problem was
unresolved directing decisions and inadequate editorial review, not too few
effects as a universal rule.

## Where the upstream check was missing

Native Short strategy validation accepted a review method and nonempty findings.
That could describe a local note without an independent pass or a binding to
the current complete plan. The request also listed scene planning before source
scouting. A later generated brief could appear complete while merely describing
HTML that had already been assembled.

The automated route already had strict review verdicts, current-input bindings
and bounded revision loops. We reused its review contract rather than adding
another orchestration framework.

## What now happens before dependent assembly

The agent completes the brief, scouts actual assets, and finishes the scene map:
spoken cue, explanatory purpose, source range and handles, crop, text, visual
development, transition, reading hold and exit. It resolves missing capabilities
and sources before building the affected scene. A fresh critic reviews that
plan and its actual evidence.

`native-short-prebuild-review.ts` validates the existing `ProducerReview` plan
result. New direct, guided and writer builds require a pass with no material
issues, seven coverage assessments, declared independent reviewer provenance
and pinned evidence. Minor findings remain allowed.

```ts
assertNativeShortPrebuildReview(input);
// Dependent native assembly and selected-media preparation follow.
```

The digest covers the authored project, including assets, source clocks, canvas,
scene decisions, captions, extension markup and motion. It excludes the review
reference itself and the generated `guidedBinding`/`preparedSources` transports.
Including those transports would create a review-reference cycle or invalidate
the review during mechanical preparation. Their existing proposal and media
validators remain mandatory.

A changed cue, crop, transition or asset invalidates the pass. A separate frozen
review sidecar survives publication and cold read. Legacy v1/v2/v3 projects remain
readable as unreviewed history; they do not receive invented approval.

## Evidence and limits

The native/guided group passed 183 tests. An independent reviewer ran 38 critical
tests and found no material code, security or compatibility issue. Shared
prompt/controller regressions confirm that a flagged editorial defect requires
repair despite passing technical QC and another passing critic.

These tests verify routing and input integrity. They do not prove that the
reviewer inspected pixels, understood the argument or predicted retention.
Arbitrary native long-form HTML remains governed by the agent-owned prebuild
and current-candidate review workflow; the Short writer gate does not cover it.

Parallel graphics workers help only after a scene has a precise assignment and
disjoint file ownership. One lead keeps dialogue, global timing and seams. Review
the integrated entrances, action, holds and exits before a full export; final
whole-program playback still follows. Record actual timing and rerender causes
before claiming the workflow is faster.
