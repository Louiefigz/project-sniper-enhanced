## What the reference does

A typed request fills the view; presenter and a brief service identity follow; a map with individual place pins then fills the upper region above the speaker.

**Type and hierarchy:** Product UI keeps its own readable text; the map scene uses a compact bold white uppercase caption near the pane boundary. UI branding is reference content, not our palette.

**Timing:** The sequence shows selected source states; inspect the original interval for exact motion, easing and spoken synchronization.

**Words and story:** The request asks for breakfast, work and sightseeing places; the map is introduced as actual places. This is a paraphrase of the relevant passage/captions, not a verbatim or phonetic transcript.

**Why this treatment helps:** Turn a place-finding request into locations the viewer can inspect.

## Apply the mechanism to a new story

**Use when:** Place, route or spatial arrangement is what the viewer needs to understand.

**Avoid when:** The spoken passage contains no spatial decision.

**Preserve:**

- The same request and relevant destinations carry into the result.
- Map detail gets enough room to identify its pins.
- Return to the presenter for interpretation after the map is understood.

**Layout and presenter:** Full input while it is read; full map during route formation; split only when route labels remain legible.

**Pacing:** Reference request holds about4.5seconds; retain enough result hold for route and stops to be inspected.

**Return to the person:** After route resolves, to explain how it changes the day or what the limitation is.

**Get these materials first:** Open the available mapping/chat workflow, choose one public example trip, record prompt submission and returned route in the same session. Save a clean wide capture plus close crops of request, place list and route. Keep city/stop names consistent; log the result source.

**Improve this limit:** Reference mixes locations across inserts. Reuse the visual mechanism, not that discontinuity; a generic map is capability illustration, not proof of the narrated itinerary.

**Do not transfer:**

- Do not change city or task between request and map.
- Do not treat a generic map as proof of the narrated itinerary.
