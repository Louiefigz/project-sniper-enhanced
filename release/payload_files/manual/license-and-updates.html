Which version you have

cat RELEASE.json

It records the version, the exact source it was built from (a commit and a source-tree id), the platform, every component version and download checksum, and — plainly — that this build is not approved for sale ("sellable": false; the open items are in PENDING-OWNER-DECISIONS.txt). Quote the version field whenever you report a problem.

The archive's own checksum is deliberately not inside the archive. It is published beside the download in SHA256SUMS, because a hash stored inside a file cannot verify that file.

Going back to an earlier version

There is no in-place rollback, and that is on purpose. Each release is a separate folder with its own runtime/:

  1. Keep the old release folder. Do not delete it when you unzip a new one.
  2. Before setting up the new one, decide where your projects live: either move the old folder's projects folder somewhere outside both (for example ~/SniperProjects) and set up each release with install/install.command --workspace ~/SniperProjects, or copy the projects you need into the new folder's projects. If you created runtime/sniper.local.env in the old folder, copy it into the new one first.
  3. Set up the new one beside the old one and open it in your agent. If it misbehaves, open the old folder in your agent instead.

Two releases set up with the same --workspace share your videos. An export that was interrupted resumes only in the release folder that started it; in the other one, export again. A project created by a newer release may use plan fields an older one does not understand — if you plan to go back, copy the project folder first.

Backup

Back up your projects folder: projects inside the Sniper folder, or the folder you chose at setup (./sniper workspace prints it). That is all of your work: your footage, your transcripts, your edit plans and your finished videos. The rest of the Sniper folder is replaceable — you can always unzip it again.

Keeping your videos somewhere else

Run setup once with install/install.command --workspace /Volumes/Work/SniperVideos, or put this one line in runtime/sniper.local.env (create the file if it does not exist):

SNIPER_WORKSPACE_ROOT=/Volumes/Work/SniperVideos

Back up that folder instead. With Codex, writing outside the Sniper folder needs its approval.

Moving the Sniper folder

If you move or copy the Sniper folder after installing, its scripts refuse to start until you run install/install.command once in the new place. It redoes only the steps that record the folder's location, and keeps your settings.

Uninstall

install/uninstall.command

Let running edits finish first; while a Sniper command still uses the folder, uninstall changes nothing and names what is using it. It asks you to type REMOVE, then removes what the installer created: runtime/ (browser, speech model, the Deepgram connection, logs, receipts), the two node_modules folders, .venv, and the render runtime and caches in templates/motion/.sniper-native-runtime. If a removal fails, it says which and exits with an error, so you can fix the cause and run it again. There is nothing to sign out: Sniper never signed in to anything.

Kept on purposeWhy
runtime/sniper.local.envYour own settings. A reinstall in this folder uses them again.
Your projects (projects, or your chosen folder)Your work.
templates/motion/.sniper-native-runtime/native-export-historyWhat an interrupted export needs to resume. A reinstall in this folder picks it up.

Uninstall also removes Sniper's own tools from ~/.project-sniper, unless another Sniper folder of the same release still uses them (it then says which one).

To finish, delete the folder — that also deletes the kept files including your projects if they are in its projects folder, so move them first. Uninstall does not touch your videos, your own Node, Python, Homebrew, conda, ffmpeg, whisper, tesseract or yt-dlp, or your own Codex or Claude Code, their settings (~/.codex, ~/.claude, ~/.claude.json) or their logins.
