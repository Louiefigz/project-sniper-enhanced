Install, first launch, and signing in

Most of the time is downloads. The installer is safe to run again: it redoes only what did not finish.

Step 0 — check the download is the file it should be

Beside the download there is a checksum file. Compare it with the archive you received:

shasum -a 256 project-sniper-<version>-mac.zip

The value must match the one in SHA256SUMS. If it does not, the file is incomplete or altered — download it again and do not install it. The real checksum is only ever published outside the archive; a hash inside a file cannot verify that file.

Step 1 — unzip somewhere sensible

Your home folder or ~/Applications is fine. Two constraints:

  • No comma, apostrophe, colon or backslash in the folder path. The audio-cleanup filter embeds this folder's path and cannot handle those characters. Any other character — spaces, accents, $, quotes — is fine: Sniper stores its settings literally. The installer checks and tells you if the path is unusable; this is a known limit, not something the installer fixes.
  • Not on a drive you unplug, and not in a folder that syncs to cloud storage — render caches are large and will fight the sync.

Step 2 — nothing to install first

Sniper brings its own tools. The first setup downloads them from conda-forge (the open-source package collection), checks every file against the SHA-256 recorded for this release before using it, and installs them into ~/.project-sniper. You do not need Homebrew, Xcode, Python, Node or any of these:

ToolVersionNeeded for
Python3.14.4the editing engine
Node24.21.0 (LTS)the app, rendering, the Codex and Claude CLIs
ffmpeg and ffprobe8.0.3, Sniper's own buildevery render
whisper.cpp1.9.3local transcription
tesseract5.5.3studying a reference video (reading its on-screen text)
yt-dlp2026.08.19adding a reference from a YouTube, Instagram or TikTok link
git2.55.0the Codex and Claude CLIs (so macOS never asks to install developer tools)

About 300 MB is downloaded once; the tools take about 1.2 GB on disk. Your own Homebrew, Python, Node or conda are not used or changed, even when they come first on your PATH. Sniper folders of the same release share one copy of the tools; uninstalling the last of them removes it. If the download stops, run setup again: it resumes and checks what arrived.

Which Macs. Apple silicon (M1 or later) with macOS 13 or later — the oldest macOS these tools support. So far only macOS 26 has actually been tested. On an Intel Mac or an older macOS, setup stops before downloading anything and says why.

Your home folder path must not contain a space (macOS account names never do): the tools live there because Studio needs a Node path without spaces, and this folder may have them.

Sniper's ffmpeg. The renderer needs two ffmpeg filters (zscale and rubberband) that no ready-made Mac build carries, so Sniper builds ffmpeg itself from the unmodified FFmpeg 8.0.3 and Rubber Band 4.0.0 sources. It ships in this download (install/deps/), with those sources and the build recipe in third-party/sources/ (GPL). Setup checks its SHA-256 and installs it the same way as the downloaded tools. It is not yet signed with an Apple Developer ID.

Step 3 — open guided setup

Double-click install/setup.command in Finder. It installs Sniper and its tools if needed, then guides you through subscription sign-in, the optional Deepgram connection and the readiness checks. When they pass it opens Sniper’s configured Codex or Claude editor. Press Enter at the subscription choice to use Codex. You do not need Cursor or a code editor.

For a scripted installation you can still run:

install/install.command --provider codex     # or: --provider claude

Your videos go to ~/ProjectSniper unless you add --workspace /path/to/folder.

Double-clicking it in Finder also works; it then asks which subscription to use. macOS may warn that a downloaded script is from an unidentified developer — right-click it and choose Open, the normal macOS prompt for a downloaded script.

What it does, in order:

  1. Installs Sniper's own tools (above) — or, when they are already there, checks every one of their files against what was installed and that each tool runs, including every ffmpeg feature the renderer uses.
  2. Installs the app's dependencies into app/node_modules (npm checks every package against the integrity hash in the lockfile).
  3. Installs the rendering project's dependencies into app/templates/motion/node_modules, the same way.
  4. Creates app/.venv from a pinned list, so you get exactly the Python package versions this release was tested with; every download must match its recorded SHA-256.
  5. Downloads the exact rendering browser into runtime/browser and checks its SHA-256 against the one recorded for this release.
  6. Puts the speech model in runtime/whisper. If an identical copy is already on your Mac it reuses it; otherwise it downloads about 465 MB. The file must match its recorded checksum.
  7. Installs the pinned Codex and Claude CLIs into runtime/cli from a reviewed lockfile (again integrity-checked by npm).
  8. Writes this install's settings to runtime/sniper.env.
  9. Builds the rendering runtime.
  10. Builds the app. This needs no internet connection.

In a Terminal window it continues into sign-in, then the optional Deepgram connection (offered only if you have not answered it before), then the checker. A noninteractive installation leaves these for you to finish by double-clicking install/setup.command.

If it stops, run it again. Each step records what it finished with and the checksum of every file it produced. A step that did not finish, whose inputs changed, or whose files no longer match is removed and redone; a finished, intact one is skipped. You never have to delete anything by hand. An interrupted download resumes from where it stopped; a partial download that turns out wrong is fetched again from the start. Your own settings in runtime/sniper.local.env are never overwritten.

The installer runs only while nothing else is using this folder: stop the app (install/stop.command), close any Sniper editor window and let running edits finish first. If something is still using it, the installer says what and changes nothing.

Step 4 — sign in, then connect Deepgram (optional)

Setup signs you in first. If you only need to repeat sign-in:

install/sign-in.command

This signs in to the subscription you chose, using this package's own copy of the CLI and its own settings folder. Your existing Codex or Claude setup and login are not used or changed. A browser window asks you to authorise with the subscription you already pay for.

  • Codex keeps this login in runtime/codex-home.
  • Claude keeps it in your macOS Keychain as its own item, separate from any Claude login you already have. install/uninstall.command signs it out.

Sniper accepts only a subscription login for the editor. An API-key login is refused on purpose, so no edit bills per call. (Only the optional Text Review uses an Anthropic API key, and only if you add one yourself and tick its opt-in; see the requirements on the start page.) To switch subscription later: stop the app (install/stop.command), run install/use-provider.command claude (or codex), then sign in again. The switch applies to the whole install at once: the app, the editor window (install/editor.command) and every edit. Asking the editor window for the other provider without switching is refused, because the app would keep using the first one.

Next, setup asks whether you want to connect Deepgram. Choose Connect/replace key, create a key at Deepgram Console, and paste it at the hidden prompt. Setup checks the key with Deepgram before saving it. A failed check keeps any previous key. You can retry or skip and use the included local transcription.

Deepgram is optional and billed separately by Deepgram. Using it sends audio to Deepgram. The connection check sends no audio and does not prove your balance or every model permission. Connecting does not authorize paid transcription: approve it for the specific edit when you ask your editor to use Deepgram.

The key is saved in runtime/deepgram.env, readable only by your Mac account, and loaded by Sniper’s launchers. It is not part of the source or diagnostic bundle. Reopen install/setup.command to replace or remove it without editing files. Removal disconnects this install; revoke the key in Deepgram Console to invalidate it.

Choosing the model

Sniper sends an explicit model with every request. This release's defaults are Opus for Claude and gpt-5.6-sol at the highest reasoning setting for Codex. Aaron's own preference is Codex with GPT-6 Astra; to use a different Codex model, create runtime/sniper.local.env containing one line:

SNIPER_CODEX_MODEL=gpt-6-astra

That file is the one place for your own settings, and it is read as shell: put a value that contains $, a backtick, a backslash, quotes or spaces in single quotes, for example SNIPER_WORKSPACE_ROOT='/Volumes/Work/Client $97'. The editor window and the app both use the model you set there.

Use the identifier your plan actually offers. Not every plan includes every model; if yours does not, the provider rejects the request and Sniper reports it rather than switching to a different model.

Step 5 — make your first edit

Guided setup opens the configured editor only after all required checks pass. Say “Help me make my first edit from my own video.” Next time, double-click install/editor.command. This opens Sniper’s terminal editor using the installed settings and connection; launching an unrelated Codex desktop window does not load them.

If you prefer the browser app, the existing check/start commands are:

install/doctor.command
install/start.command

The checker asks the product's own code what it would use, runs a short real transcription of speech it generates on your Mac, and signs in the way a real edit does, without running an edit. start.command waits until the app is serving this build, then opens http://127.0.0.1:3000. If the port is busy it names the program holding it.
