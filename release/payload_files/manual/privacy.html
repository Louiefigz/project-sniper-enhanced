What leaves your computer, and what does not

Checked against the code in this package, feature by feature. Read this before you edit anything confidential.

Sniper's own commands never upload a video file, and audio leaves only if you explicitly authorize the optional paid Deepgram transcription. Rendering, speech-to-text and the media work run on this computer. You edit by talking to your own Codex or Claude Code: what it reads and sends in that conversation — transcripts, plans, still frames it looks at — goes to its provider under your account, as any conversation with it does.

Still images of your footage do leave. Before your agent hands you a finished edit, it reviews the rendered result: still frames from the video go to your provider so it can check them. This happens for trim-only edits too; there is no text-only mode.

Your agent can read your files. Codex or Claude Code works with file tools in the Sniper folder and wherever your footage is. Sniper's instructions tell it not to attach or upload video or audio, but that is an instruction, not something Sniper's code can enforce. See your editing agent below.

Your editing agent

You edit by talking to your own Codex or Claude Code, with the Sniper folder open. It reads the transcript, the rules and the project, and runs Sniper's commands. What that means:

  • Claude Code has file tools that can read any file your account can read, and asks you before running a command you have not allowed.
  • Codex runs commands in its own sandbox, which limits where it can write (normally the Sniper folder, where your projects are), not what it can read. Sniper's video check starts its own macOS sandbox on Mac, which cannot start inside Codex's, so Codex asks you to approve running that step outside its sandbox; the check itself still runs sandboxed. A full edit through Codex has not yet been run for this release.

Sniper's video/audio sandbox wraps the media decoder, not your agent. On macOS, the OS does not allow that sandbox inside another one; on Windows the decoder uses a disposable AppContainer. If a still frame of a recording must never leave your computer, do not edit that recording with Sniper; the rendered review sends frames every time.

What that means in practice

  • Your words, as a transcript, go to your provider. So do still pictures of your edited video.
  • Your provider's data policy for your plan governs what happens to them. Sniper does not change it and cannot see it.
  • The optional paid Deepgram transcription stays off unless you add a key and approve it for a run. Nothing falls back to it.

Where your files live

projects/<project>/      (inside the Sniper folder, unless you chose another at setup)
  source/     your footage and its transcripts
  producer/   edit_plan.json, base_final.mp4, final.mp4
  segments/   Segmenter exports
  clipper/    Clipper timelines

Uninstalling keeps it, but deleting the Sniper folder deletes it too, and a new release comes in a new folder: move projects first, or point setup at it — see Licence, updates, backup and uninstall.
