## Apply the mechanism to a new story

**Use when:** The lesson promises a concrete output or working product.

**Avoid when:** Only a hypothetical mockup exists but the words claim a completed real result.

**Preserve:**

- The actual resulting interface fills enough of the frame to inspect.
- Keep the same task identity from request to result.
- Hold the resulting state after any action.

**Layout and presenter:** Full input/constraints; split for site introduction; full form close-up for the operation.

**Pacing:** Reference prompt is about2.4seconds; form result needs at least a settled reading window after the action.

**Return to the person:** After the tested result, for the limitation or how the viewer can reproduce it.

**Get these materials first:** Use an owned test project. Obtain the actual generated page, record navigating to the form, entering permitted sample data, clicking and showing the response. Keep any live external submission inside an authorized demo environment.

**Improve this limit:** A highlighted input is not evidence of a pull request or successful submission. Capture those outcomes separately if claimed.

**Do not transfer:**

- No decorative browser skeleton in place of the supplied result.
- A visible form is not evidence of successful submission.
