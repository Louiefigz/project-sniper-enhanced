Install, first launch, and signing in

About fifteen minutes, most of it downloads. The installer is safe to run again if it stops.

Step 0 — check the download is the file it should be

Beside the download there is a checksum file. Compare it with the archive you actually received:

shasum -a 256 project-sniper-<version>-mac.zip

The value must match the one in SHA256SUMS. If it does not, the file is incomplete or altered — download it again and do not install it.

Do not use any hash printed inside the archive to check the archive. That cannot work. The real value is only ever published outside it.

Step 1 — unzip somewhere sensible

Put the folder where you keep applications or work — your home folder, or ~/Applications. Two constraints:

  • Not inside a path containing a comma, an apostrophe, a colon or a backslash. Those characters break the audio-cleanup filter, because it embeds this folder's path. Spaces and accented letters are fine. The installer refuses and tells you if the path is unusable.
  • Not on an external drive you unplug, and not in a folder that syncs to cloud storage — the render caches are large and will fight the sync.

Step 2 — install what you do not already have

The installer requires four free tools to be present and installs everything else itself. If any are missing it stops and tells you the one command to run:

# Node 22 or newer  —  https://nodejs.org  (choose LTS)
# Python 3.11 or newer  —  https://www.python.org/downloads/macos/
brew install ffmpeg
brew install whisper-cpp

Step 3 — run the installer

install/install.command

In Finder you can double-click it. macOS may warn that it is from an unidentified developer; right-click and choose Open to allow it, which is the normal macOS prompt for a downloaded script.

It has eight steps and prints each one. It installs into this folder's runtime/ directory:

  1. Checks Node, Python, ffmpeg and whisper-cli.
  2. Installs the app's two dependency sets.
  3. Creates the Python environment from a pinned list, so you get the exact package versions this release was tested with.
  4. Downloads the exact rendering browser (about 150 MB). Sniper deliberately never downloads a browser during a render, so this has to succeed once.
  5. Downloads the speech model (about 465 MB) and verifies its checksum.
  6. Installs the pinned Codex and Claude CLIs inside this package.
  7. Writes this install's settings and creates ~/ProjectSniper.
  8. Builds the rendering runtime and runs the checker.

If it stops partway, run it again. Every step checks what is already correct and skips it. It never deletes work you already have.

Step 4 — sign in to Codex or Claude

You only need one. Run the command for the one you use, from Terminal in this folder:

# Codex
runtime/cli/node_modules/.bin/codex login

# Claude
runtime/cli/node_modules/.bin/claude auth login

Why the long path. These are this package's own copies, pinned to the exact versions this release accepts, with their own settings folder under runtime/. Signing in this way does not change your existing Codex or Claude login, and an auto-update to your own CLI cannot break Sniper.

You will be asked to authorise in a browser, using the subscription you already pay for. Sniper refuses an API-key login on purpose: it is built to use your subscription, not to bill you per call.

Choosing the model

Sniper sends an explicit model with every request rather than inheriting whatever your CLI defaults to. This release's defaults are Opus for Claude, and gpt-5.6-sol at the highest reasoning setting for Codex. To use a different Codex model — Aaron's own preference is GPT-6 Astra — add one line to app/.env.local:

SNIPER_CODEX_MODEL=gpt-6-astra

Use the identifier your plan actually exposes. Not every subscription tier includes every model; if the model is unavailable the provider rejects the request and Sniper reports it rather than silently downgrading.

Step 5 — start it

install/start.command

It waits until the app answers, then opens http://127.0.0.1:3000. If the port is busy it names the program holding it. Stop it with install/stop.command.

The app listens on loopback only, so nothing else on your network can reach it.

If the checker reports a problem

install/doctor.command

It prints the actual resolved path for every component and marks the failing lines. When something goes wrong lists what each message means.
