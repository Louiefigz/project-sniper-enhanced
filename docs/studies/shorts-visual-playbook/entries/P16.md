## Apply the mechanism to a new story

**Use when:** The lesson requires delegation, separate outputs and aggregation or feedback.

**Avoid when:** There is only a central hub without a directional work/return sequence.

**Preserve:**

- Distinct outgoing branches, each connected to its own output.
- Visible return/aggregation path to the original chief.
- Stable overview after the relationship has been revealed.

**Layout and presenter:** Full visual if branch labels need room; split only with short labels and sufficient top-stage height.

**Pacing:** A two-second reference glimpse establishes a category but cannot teach a complex loop; plan3–6seconds or simplify to one branch before expanding.

**Return to the person:** After outputs converge, to say what decision the chief enables.

**Get these materials first:** Write the three assignments and concrete outputs from the lesson. Create only those nodes. If claiming live delegation, capture real role runs and attach their actual results instead of fake completion badges.

**Improve this limit:** Color changes cannot repair wrong relationship anatomy. A simple hub lacks distinct stage/feedback meaning.

**Do not transfer:**

- Do not call a hub or a simple list an equivalent.
- Do not show a feedback arrow unless the described process has that feedback.
