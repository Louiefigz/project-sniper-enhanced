When something goes wrong

What to expect, what the checker tells you, and how to send something useful if you get stuck.

First move, always

install/doctor.command

It asks the product's own code which browser, ffmpeg, speech model and provider CLI a render would actually use, and prints each one. It marks a line FAIL only for something that has to work, GATED for an optional feature that is not installed, and INFO for something worth knowing. If every required line passes, the install is fine and the problem is in the edit, not the setup.

The media admission (real sample) line runs a generated sample clip through the same admission step your footage goes through. If it fails, Producer cannot start an edit, and the line says why. What this candidate does and does not do yet is listed in PENDING-OWNER-DECISIONS.txt.

The line names each one.Stop the app (install/stop.command), close the editor window, let edits finish, then run it again. Nothing was changed.

Your home folder path contains a space …Sniper keeps its tools in your home folder, and Studio cannot use a Node whose path has a space. macOS account folders never have one, so this means the home folder was renamed.Use a Mac account whose home folder has no space in its path.

Downloading [n/N] … stopped before it finished (curl error …)The internet connection dropped while setup was downloading Sniper's tools.Run setup again when your connection is stable; it resumes where it stopped and checks every file.
… produced the wrong file (checksum mismatch); it was deleted.A downloaded file did not match the SHA-256 recorded for this release — usually a network filter or proxy that changed it on the way.Run setup again. If it happens again on the same file, try another network and run install/diagnostics.command.
Sniper's own tools — changed since they were installed …; reinstalling them. A file in ~/.project-sniper was changed or removed.Nothing to do: the installer puts the tools back from the checked downloads.
Sniper's own tools are not installed yet. or Sniper's own Node cannot be used: … ~/.project-sniper was removed or damaged.Double-click install/setup.command (or run install/install.command); it reinstalls them.
Another Sniper installer is setting up the same tools; waiting …Two Sniper folders are being set up at once; they share the same tools.Nothing to do: the second one continues when the first has finished.
This install's editor brain is codex. An editor window on claude would disagree … You asked the editor window for the provider this install does not use.Switch the whole install: install/stop.command, then install/use-provider.command claude.
no cached chrome-headless-shell foundThe rendering browser is missing. Sniper never downloads one mid-render on purpose.Run the installer again; step 5/10 downloads it and checks its SHA-256.
WHISPER_CPP_MODEL does not exist: …The speech model is missing or was moved. Run the installer again; step 6/10 re-downloads it and checks its checksum.
Port 3000 is already in use by: …Something else holds the port. The message names it.Quit that program, or start on another port: SNIPER_PORT=3100 install/start.command
The folder path contains one of , ' : \ …Those characters break the audio-cleanup filter, which embeds this folder's path.Move the folder somewhere without them. Spaces, accents, $ and quotes are fine.
A render stops and reports a problemWorking as designed. Sniper stops rather than shipping something it could not check.Read the message: it names the lane and the reason. Most are a request to pick a style or confirm a choice.
Not enough disk spaceA long render needs tens of GB of temporary space. Stop the app, then install/clean-caches.command shows what can be freed and how big it is, and never touches your footage, plans, finals or unsynced edits.

What to realistically expect

The only timing on record is Aaron's own: he fully edits a ten-minute video — motion graphics, cuts, trims, audio correction, b-roll — in under three hours, and estimates Sniper saves him about 85% of the effort versus editing it by hand. That is one person's report about his own work on his own machine. It is not a promise about your recording, your Mac or your provider plan, and no typical buyer runtime has been measured. Your first edit will take longer than your tenth, because you are learning what to ask for.

  • Transcription is local and roughly real-time-ish on Apple silicon; a 30-minute recording is minutes, not seconds.
  • Planning and review are provider calls. They are the slow part, and your plan's rate limits apply.
  • Rendering is CPU and disk heavy. Expect the fans.
  • An edit keeps running if you close the browser tab or restart the app. It is a separate background process on purpose.

Sending something useful

install/diagnostics.command

This writes a folder to your Desktop containing structured facts only: this build's RELEASE.json, your macOS, Node and Python versions, the checker's report, the installer's own step log, and counts of app-log lines by kind. It does not copy app-log text, footage, transcripts, edit plans or logins. If support asks for more, install/diagnostics.command --include-app-log adds the last 200 app-log lines after redaction — pattern redaction cannot promise to catch everything, so read them before you send them.

Support is not settled for this candidate. There is no support address in this package because the support route and response commitment have not been decided. Do not treat any address you find in the source as a support channel.
