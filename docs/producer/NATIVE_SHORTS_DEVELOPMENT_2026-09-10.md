## What now executes

The explicit V9 contract carries selected reference IDs, actual source word
occurrences and quotes, visible objects, initial state, source-cued actions,
result state, reading holds, views and stable scene IDs through:

1. Existing guided input preparation and exact speech/frame evidence.
2. Selected individual reference-image snapshots and explicit Codex attachments.
3. Deterministic compilation, existing immutable proposal storage and cold read.
4. An isolated native project writer with separate source video cuts, dialogue
   cuts, word-caption elements and editable scene HTML.

The supported development mechanisms are a contained presenter hold and a
persistent original message illustration. Source cuts are preserved. Missing
required outside assets, disabled/operator-owned lanes, music requests, changed
source quotes, wrong word cues, incomplete coverage and insufficient authored
reading time block execution. A valid seven-second result hold is allowed; a
presenter hold has no mandatory graphics or punch-in quota.

Native scene IDs cannot occupy root/media/caption namespaces or collide with
another generated scene mount. A scoped copy revision preserves the footage and
caption HTML; changing the source cut rejects the old compiled direction. This
is not yet incremental export or a user-facing revision system.

The default proposal schema remains V5. V9 is currently an explicit internal
qualification seam. Existing legacy readiness, opening and body executors refuse
V9. The normal application buttons do not yet select this route or call the new
project writer. An HTML output alone must not be described as shipped UI behavior.
