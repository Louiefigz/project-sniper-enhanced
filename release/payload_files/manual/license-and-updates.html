The commercial terms, what version you have, and how to remove Sniper without losing your videos.

What you may do with it — selected terms

The restrictions are about the software, not about your videos.

Third-party components inside Sniper keep their own licences, which are yours to follow too. They are listed in THIRD-PARTY-NOTICES.md beside this manual — that file is part of the licence, not a formality.

Updates — read this one carefully

Your purchase is the version you downloaded. It does not include bug fixes, compatibility updates or new versions. Later releases are part of the separate paid support and updates offer.

Because that is the policy, here is the honest risk, stated rather than hidden:

RiskHow exposed you are
Your own Codex or Claude CLI auto-updatesHandled. This package installs its own pinned copies of both CLIs inside runtime/ and disables their auto-updater. An update to your global CLI does not affect Sniper.
A Python or Node package changes underneath youHandled. Both dependency sets and every Python package are pinned to exact versions, so a reinstall gets the same set this release was tested with.
Your provider retires the model, or changes what its sign-in check reports Not handled, and not fixable by you. Sniper checks the sign-in response strictly. If your provider changes it, this version stops being able to sign in, and a fix would be a new release you do not have rights to under this policy.
A major macOS upgrade breaks a dependencyNot handled. Same reason.

If those risks matter to you over a period of years, the paid support and updates offer, not this purchase, is what covers them.

Which version you have

cat RELEASE.json

It records the version, the exact source it was built from, the platform it is qualified for, every component version, and — plainly — whether this build is sellable and what is blocking it. Quote the version field in any support message.

The archive's own checksum is deliberately not inside the archive. It is published beside the download in SHA256SUMS, because a hash stored inside a file cannot verify that file.

Going back to an earlier version

There is no in-place rollback, and that is on purpose. Each release is a separate folder with its own runtime/:

  1. Keep the old release folder. Do not delete it when you unzip a new one.
  2. Install the new one beside it and use it.
  3. If the new one misbehaves, stop it and start the old one.

Both point at the same ~/ProjectSniper, so your videos are shared between them. A project created by a newer release may use plan fields an older one does not understand — if you plan to go back, copy the project folder first.

Backup

Back up ~/ProjectSniper. That is all of your work: your footage, your transcripts, your edit plans, your finished videos and your approval receipts. The Sniper folder itself is replaceable — you can always unzip it again.

Include ~/.project-sniper/config.json if you moved your workspace somewhere other than the default.

Uninstall

install/uninstall.command

It asks you to type REMOVE, then deletes only what the installer created: runtime/, the two node_modules folders and the Python environment. Then delete the folder.

It does not touch your videos in ~/ProjectSniper, your own Node, Python, Homebrew, ffmpeg or whisper install, or your global Codex and Claude CLIs and their logins.
