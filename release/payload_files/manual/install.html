Install and first use

You use Sniper from your own Codex or Claude Code: open the Sniper folder there and ask. Setup is mostly downloads, and it is safe to run again: it redoes only what did not finish.

Step 0 — check the download is the file it should be

Beside the download there is a checksum file. Compare it with the archive you received:

macOS:   shasum -a 256 project-sniper-<version>.zip
Windows: Get-FileHash project-sniper-<version>.zip -Algorithm SHA256

The value must match the one in SHA256SUMS. If it does not, the file is incomplete or altered — download it again and do not install it. The real checksum is only ever published outside the archive; a hash inside a file cannot verify that file.

Step 1 — unzip somewhere sensible

Your home folder or ~/Applications is fine on macOS. On Windows, use a normal local folder such as C:\Users\you\Project Sniper. Two constraints:

  • No comma or apostrophe in the folder path. On macOS, also avoid a colon or backslash. The audio-cleanup filter embeds this folder's path and cannot handle those characters. Any other character — spaces, accents, $, quotes — is fine: Sniper stores its settings literally. The installer checks and tells you if the path is unusable; this is a known limit, not something the installer fixes.
  • Not on a drive you unplug, and not in a folder that syncs to cloud storage — render caches are large and will fight the sync.

This folder is the one you open in Codex or Claude Code. Your video projects go in its projects folder unless you choose another (see Step 3).

Step 2 — nothing to install first

Sniper brings its own tools. The first setup downloads them from conda-forge (the open-source package collection), checks every file against the SHA-256 recorded for this release before using it, and installs them into ~/.project-sniper on macOS or %LOCALAPPDATA%\ProjectSniper on Windows. You do not need Homebrew, Xcode, Python, Node or any of these:

The platform runtime is downloaded once (the Windows lock is about 0.57 GiB before the browser, model and JavaScript packages; totals vary by platform). Your own Homebrew, Python, Node or conda are not used or changed, even when they come first on your PATH. Sniper folders of the same release share one copy of the tools; uninstalling the last of them removes it. If the download stops, run setup again: it resumes and checks what arrived.

Which computers. Setup selects one of three locked targets: macOS 13.5 or newer on Apple silicon, macOS 14 or newer on Intel, or 64-bit Windows 10 22H2 (build 19045) or newer. Apple silicon is the developer platform. Native Intel setup, repeat setup, the full doctor and the launcher are exercised on a macOS 15 Intel runner. Windows x64 is installed and checked on a clean Windows Server 2025 runner. Unsupported systems stop before downloads.

On macOS, your home folder path must not contain a space: the shared tools live there because Studio needs a whitespace-free Node path. Windows uses explicit executable paths and does not have that restriction.

Sniper's ffmpeg. On macOS, Sniper ships its own FFmpeg 8.0.3 and Rubber Band 4.0.0 build because the renderer requires zscale and rubberband. The matching source and recipe ship under third-party/sources/ and inside the archive. On Windows, setup downloads the pinned BtbN FFmpeg 8.1.3 GPL build with those features. Every artifact is checked by size and SHA-256. The macOS executable is not yet signed with an Apple Developer ID.

Step 3 — open the folder in Codex or Claude Code and say “Set up Sniper”

You need your own Codex (a ChatGPT plan) or Claude Code (a Claude plan), desktop app or command line, signed in as usual. Sniper installs no copy of either and never asks you to sign in to anything: it runs on the subscription you already use. Open this folder there and ask:

Set up Sniper.

Your agent runs ./sniper setup on macOS or sniper.cmd setup on Windows, which takes several minutes, mostly downloads. It asks your permission before running commands, as it always does. With Codex, it may also ask to run a step outside its own sandbox: setup downloads outside the package folder. On macOS, Sniper's video check starts its own sandbox, which cannot start inside Codex's; approve that step outside Codex's sandbox. On Windows, untrusted media runs in a disposable, networkless AppContainer with bounded CPU and memory.

If you prefer not to let your agent install, double-click install/setup.command in Finder instead: it does the same in a Terminal window. It is not yet signed, so the first time macOS stops it. On macOS 13.5–14, right-click it and choose Open. On macOS 15 or later that no longer works: after the warning, open System Settings › Privacy & Security and click Open Anyway next to the message about the script. The Gatekeeper click-through route still needs an outside-operator check on a clean Mac. On Windows, open Command Prompt or PowerShell in this folder and run sniper.cmd setup.

Your projects go in this folder's projects folder, where Codex can work without extra approvals. To keep them somewhere else, run setup once with install/install.command --workspace /path/to/folder on macOS or sniper.cmd setup -Workspace C:\path\to\folder on Windows (Codex may ask before it writes outside the open folder).

What setup does, in order:

  1. Installs Sniper's own tools (above) — or, when they are already there, checks every one of their files against what was installed and that each tool runs, including every ffmpeg feature the renderer uses.
  2. Installs the JavaScript dependencies Sniper's scripts use into node_modules (npm checks every package against the integrity hash in the lockfile).
  3. Installs the rendering project's dependencies into templates/motion/node_modules, the same way.
  4. Creates .venv from a pinned list, so you get exactly the Python package versions this release was tested with; every download must match its recorded SHA-256.
  5. Downloads the exact rendering browser into runtime/browser and checks its SHA-256 against the one recorded for this release.
  6. Puts the speech model in runtime/whisper. If an identical copy is already on your computer it reuses it; otherwise it downloads about 465 MB. The file must match its recorded checksum.
  7. Writes this install's settings to runtime/sniper.env.
  8. Builds the rendering runtime.

Then it runs the checker (./sniper doctor on macOS or sniper.cmd doctor on Windows). The macOS setup window also offers the optional Deepgram connection; on Windows use sniper.cmd connections (Step 4).

If it stops, run it again. Each step records what it finished with and the checksum of every file it produced. A step that did not finish, whose inputs changed, or whose files no longer match is removed and redone; a finished, intact one is skipped. You never have to delete anything by hand. An interrupted download resumes from where it stopped; a partial download that turns out wrong is fetched again from the start. Your own settings in runtime/sniper.local.env are never overwritten.

Setup runs only while no Sniper command is running: let running edits and renders finish first. If something is still using this folder, setup says what and changes nothing.

Step 4 — connect Deepgram (optional)

Local transcription is included and needs no key. If you also want Deepgram, double-click install/setup.command in Finder on macOS (or run it in Terminal), or run sniper.cmd connections on Windows, and choose Connect/replace key. Create a key at Deepgram Console and paste it at the hidden prompt — in that Terminal window, never into a conversation with your agent. Setup checks the key with Deepgram before saving it. A failed check keeps any previous key. You can retry or skip.

Deepgram is billed separately by Deepgram. Using it sends audio to Deepgram. The connection check sends no audio and does not prove your balance or every model permission. Connecting does not authorize paid transcription: approve it for the specific edit when you ask your agent to use Deepgram.

The key is saved in runtime/deepgram.env, readable only by your computer account, and loaded by Sniper's commands. It is not part of the diagnostic bundle. Reopen the same connection command to replace or remove it without editing files. Removal disconnects this install; revoke the key in Deepgram Console to invalidate it.

Which model

Whatever you use in your Codex or Claude Code. Sniper does not choose or send a model; its instructions and skills work with either app. Your own settings for Sniper's commands (for example a different video folder, SNIPER_WORKSPACE_ROOT='/Volumes/Work/Client $97') go in runtime/sniper.local.env. On macOS it is read as shell, so quote special values. On Windows use one literal KEY=value per line without shell quoting; spaces, $ and backslashes are preserved as written.

Step 5 — make your first edit

With the Sniper folder open in Codex or Claude Code, say “Help me make my first edit from my own video.” Your agent reads Sniper's instructions and skills from this folder and runs Sniper's commands through ./sniper on macOS or sniper.cmd on Windows, which uses Sniper's own tools whatever else is on your computer.

To check the install at any time, ask your agent to run ./sniper doctor on macOS or sniper.cmd doctor on Windows. The checker asks the product's own code what it would use, admits a generated video sample through Sniper's own sandbox and runs a short real transcription of speech it generates on your computer, without running an edit.
