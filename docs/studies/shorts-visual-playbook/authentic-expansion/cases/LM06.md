# LM06 · A workflow of artifacts above the presenter

Version `2026-09-10.3` · [Original reel](https://www.instagram.com/reel/DcUXjRkRTVu/) · 29.744s

**Message:** Test candidate headlines, use the winning wording, then inspect page performance and recommendations.

**Story:** Result promise → ad examples → budget input → metrics comparison → headline replacement → page diagnostic → recommendation result → return to presenter.

**Format foundation:** The viewer needs to inspect the thing being discussed. The upper artifact changes as the work advances, while the lower person maintains explanation and continuity. This is a clear companion to Nate's UI demonstrations, despite belonging to Lewis's account.

**Good adaptation:** Show the actual input, relevant action and changed result at readable scale. Preserve object identity across stages. Keep the presenter deliberately framed and secondary while the screen is the teaching target. Promote a dense result to full visual or focus its relevant region if a split cannot make it readable.

**Limits and counterexample:** Do not use generic software screenshots or assume displayed performance is independently verified. The visible metric rows do not clearly establish that the later replacement headline is the same winner; our adaptation must preserve that lineage. Some scrolling results move too fast for detailed reading. Bright sky also weakens CTA contrast.

**Text roles:** Small white lower speech captions, upper white CTA, and typography embedded in actual-looking pink artifact captures. Capture text and overlay captions have different roles and should not duplicate each other unnecessarily.

**Compare:** LM07, N10-B19, N03-B06. See [Format foundations](../../FORMAT_FOUNDATIONS.md).

**Possible mechanisms:** `browser-device-stage`, `ui-focus-zoom`, `native-stacked-media`. These require configuration/composition and review; they are not rendered matches.
